# Data seed — 2026-08-20

What was written into the database, what it was written from, and the eleven
things that turned out to be wrong along the way.

Before this run the schema was fully applied and **every content table was
empty**: 0 catalog_content rows, 0 geo_locations, 0 attribute_option_values, and
0 of 36,470 localized slugs. The catalog had 5,231 nodes and no way to reach any
of them by URL.

## 2. Slugs

The decision the README had deferred: **separator-aware slugify, plus a brand
override table.**

The previous `slugify` deleted every unsafe character with no replacement, which
merged distinct numbers:

| Input | Old rule | New rule |
|---|---|---|
| `nokia-8.3-5g` | `nokia-83-5g` ← 8.3 became 83 | `nokia-8-3-5g` |
| `skoda-fabia-1.5-tsi` | `skoda-fabia-15-tsi` | `skoda-fabia-1-5-tsi` |
| `bekant-sit/stand-desk` | `bekantsitstanddesk` | `bekant-sit-stand-desk` |
| `levi's-512` | `levis-512` ✓ | `levis-512` |
| `h&m-tote-bag` | `hm-tote-bag` ✓ | `hm-tote-bag` (hm.com) |
| `pull&bear-eco-hoodie` | `pullbear-eco-hoodie` | `pull-and-bear-eco-hoodie` (pullandbear.com) |

98 rows contained an ampersand, in two shapes. Tight `pull&bear` is a brand's own
orthography and each brand has already decided how it spells itself without one,
so the override table follows the brand's **own domain**. Spaced `Play & Charge`
is prose and takes the conjunction of the language being slugified — `et`, `y`,
`e`, `و`, `и` — never an English "and" spliced into an Arabic name.

Latin diacritics fold (`Sedán` → `sedan`); Arabic, Devanagari and Cyrillic never
transliterate (`Электроника` → `электроника`). Arabic harakat and tatweel are
stripped so one name cannot become two URLs; Devanagari matras are kept because
they are load-bearing.

The rule lives in `_slugify.mjs` with a **53-fixture contract**, and
`src/features/catalog-content/lib/slugify.ts` is asserted byte-identical against
it by `_slugify-parity.mjs`.

**No `catalog_slug_history` rows were written.** No catalog slug has ever appeared
in a URL — browsing is query-string based today — so there is nothing to redirect
from, and 36,617 history rows would only poison the resolver's last-resort
lookup. `--history` exists for any later re-run.

## 3. Cities

`geo_locations` is seeded from **OpenStreetMap**, not from a hand-written table.

`_geo-cities.mjs` holds only the editorial decision — *which* cities deserve a
page. Everything factual comes from Nominatim and is cached in
`geo-cities-resolved.json`, which is committed so the seed replays on staging and
prod without hitting a public API.

Coverage is **every country in `COUNTRY_DEFAULT_LOCALE`** — all 86 that map to one
of the seven locales — plus the two English-default markets already seeded:

| Locale | Countries | Cities |
|---|---:|---:|
| ar | 24 | 223 |
| es | 21 | 114 |
| fr | 31 | 104 |
| ru | 4 | 38 |
| en (US, GB) | 2 | 32 |
| hi | 1 | 25 |
| it | 3 | 23 |
| **total** | **86** | **556** |

Arabic is deepest by design: Egypt alone has 54 (all governorate capitals, the new
cities, the Red Sea and Sinai tourist economy). The French block reaches into West
and Central Africa and the overseas départements, and the Spanish block into Latin
America, because those are where those locales' inventory will come from.

The reason is the localized names. `Шибин-эль-Ком` is the real Russian name for
Shibin El Kom and `شبين الكوم` the real Arabic one; no careful transliteration of
an English string produces either. OSM localized-name coverage: `ar 483`, `ru 496`, `fr 450`, `es 417`, `hi 287`, `it 263` of 556
cities. Where OSM has no name in a language, the English name is used — never an
invented one.

**English names are ours, though.** OSM's `name:en` is academic transliteration:
it wanted to store Sohag as "Suhaj", Ismailia as "Al Ismailiyya", and — worst —
London as "City of London", which is the square mile of the financial district
rather than the city. Since `city` is both the display name and the base slug,
that would have put `/catalog/…/in-suhaj` on a page for a city everyone spells
Sohag.

Twelve cities were **omitted rather than seeded wrong**: OSM has no settlement
node for them, only the governorate, region or province that contains them —
Salalah, Sohar, Seeb, Barka, Al Rayyan, Umm Salal, Farwaniya, Latakia, Djibouti
City, Nzérékoré, Kankan, Kara. A city page that does not exist costs one long-tail
URL; a page headed "Salalah Province" with a centroid tens of kilometres out is
visibly machine-made.

Three resolver rules came out of the wider country set, each from a real wrong
answer rather than from theory:

- **Nominatim does not index every ISO code as a country.** `countrycodes=pr`
  returns *zero* results — OSM files Puerto Rico under `us` and every French
  overseas département under `fr` — and "no results" is indistinguishable from a
  misspelled city. Twelve territories failed this way. `NOMINATIM_COUNTRY_ALIAS`
  now queries with the code OSM indexes while the stored `country` stays the real
  ISO code.
- **The `place_rank` floor had to come down to 7.** Six capitals *are* their own
  first-level division, so the city and the boundary are one object: N'Djamena,
  Asunción, Niamey, Conakry, Bangui and Mopti sit at rank 8, and Minsk at 7. A
  country is still rank 4, and the real guards are the settlement-type preference
  and the container-name rejection.
- **Among same-type hits, the MORE specific feature wins.** Sorting `place_rank`
  ascending picked "Brazzaville (department)" over "Brazzaville (municipality)"
  and Luxembourg-the-country (rank 4) over Luxembourg-the-city (rank 15). It now
  sorts descending, and a trailing parenthetical is stripped before the
  container-name test so "(municipality)" does not read as a container.

Every new city was spot-checked against independently known coordinates. 23 of 24
landed within 11 km; the one that did not — Ecuador's Santo Domingo, 278 km out in
Santa Elena Province — was caught by that check and fixed with an explicit query.

## 4. Facets

`seo_role` is declared in `_facet-policy.mjs` with a reason on every line —
`storage` is `path` because "iphone 13 256gb" is the highest-volume attribute
query in phones; `clothing-size` is `query` because size is personal, not a
search phrase; `mileage` is `banded` because `/3-series/127843-km` has an
audience of one.

**The two-path-attributes-per-subcategory cap could not be enforced in the data.**
`seo_role` lives on `attribute_definitions`, which is global, while the cap is
per-subcategory. Satisfying it globally would mean demoting storage, colour,
screen size *and* body type — throwing away "iphone 13 256gb" to protect a rule
whose own field description says `url_priority` decides "which attribute wins the
single path slot". So the cap is applied at resolve time by `url_priority`, and
`08-check` now fails on a **tie at the 2-attribute cut** — the case where which
attribute gets a URL would be decided by database row order and could change
between deploys with nobody editing anything.

`raw_variants` matters more than the slugs. A facet page filters listings on
`listings_attribute_values.value`, and sellers do not agree on spelling; if
`/iphone-13/256gb` queries `value = '256'` only, it shows a fraction of its own
inventory and looks thin to both the user and the crawler. Each option row
therefore carries every spelling that means it, assembled from the declared
option, generated variants, the six localized labels, and values **actually
present** in `listings_attribute_values` and `models_attribute_values`.

Unmatched real values are **reported, never auto-created** — a facet page for a
typo is a real page with zero listings — and split by whether the attribute can
produce a URL at all, so an unrecognised `processor` value (role `query`, never a
path segment) does not drown out an unrecognised `storage` value.

## 6. Eleven things that were wrong

Recorded because each was invisible until something specific surfaced it.

1. **Two flows fire on every translation write.** `Marketing Content / Revalidate`
   and `/ Generate` are armed on all five catalog collections *and* all five
   translation collections. A 36,470-row slug backfill is therefore 36,470
   revalidate webhooks plus 36,470 generate triggers — measured at ~193 ms per
   row, about two hours of wall clock spent entirely on flow dispatch, and a real
   AI bill the moment `generation_enabled` is on. `_flow-guard.mjs` now pauses
   them; throughput went from ~2 rows/sec to ~15.

2. **`findNode` matched translation slugs in ANY language.** The resolver's `_or`
   had no `languages_code` filter, so entity A's English slug and entity B's
   Italian slug both answered the same URL — two rows returned, lowest id wins,
   one entity permanently unreachable. Now scoped to the requesting locale.

3. **A localized slug could collide with a sibling's BASE slug.** 1,176 base slugs
   carry a `-2` suffix their localized names do not, so an un-suffixed localized
   slug naturally lands on a sibling's base slug — same ambiguity as (2), by a
   different route. The backfill now claims against both sets.

4. **`08-check`'s city-prefix rule was pure false positives.** One flat list of
   geo markers was tested against every slug in every language, so `a-class` (the
   Mercedes A-Class) failed on the *French* marker and `v-vivo-v23`, a French
   slug, failed on the *Russian* one. Now language-scoped, and cross-language only
   for option values — which genuinely share the geo segment's slot.

5. **`03-seed-settings.mjs --force` reset `generation_enabled` to false.** The only
   symptom was every node in a backfill returning
   `{ skipped: "catalog_generation_disabled" }`, which reads like a broken
   pipeline rather than a switch flipped by a tool run for an unrelated reason.
   Now in `FORCE_PROTECTED`.

6. **The readiness probe was cached.** A `GET` route handler with no `dynamic`
   export served a stale `generation_enabled: false` for an hour after the switch
   was turned on. A cached kill switch is not a kill switch: the generation path
   now reads settings through `getCatalogSettingsFresh()`, and the route is
   `force-dynamic`.

7. **`/api/revalidate` had no catalog handling at all.** Every catalog write fell
   into `revalidatePath('/', 'layout')` — purging the entire app to reflect one
   renamed model. Now a collection→tag map, with the unmapped case logged rather
   than silently purging everything.

8. **The gate blocked on "this page".** Check 12 treated any page self-reference
   as prompt leakage, so an otherwise clean draft — 14 of 15 checks passed,
   quality 0.93, real Egypt prices — was routed to the review queue AND its six
   other languages were skipped, because a failed English pass stops the run. Now
   split: prompt/payload/model references block, page self-reference warns. The
   prompt was also told to avoid the phrase.

9. **The junk-data detector flagged real brands.** A `length <= 3` rule caught BMW,
   LG, HP, EA, Kia, TCL, JLL, NUK and H&M, which made the whole report ignorable.
   Now it catches the ten rows that are actually test data.

10. **`models_attribute_values` is not a normalised store.** 19,472 of 19,485 rows
    have `attribute_definitions_id = NULL`, with the spec *key* in `value` and the
    *value* in `available_options`. Reading only the FK shape returns 13 specs for
    the whole catalog, and every model page would claim it has no specs. It is a
    free-text spec sheet: usable as content context, unusable as a facet source.

11. **Nominatim's top hit is not a place.** "Umm Salal Muhammed, Qatar" returns a
    lighting shop; "Djibouti" returns the country; "Muharraq" returns the
    governorate, whose centroid is in the sea. The resolver needs all three of a
    category filter, a `place_rank` floor and a container-name rejection — and it
    was the *name* check, not the rank, that proved reliable across 29 countries.

## 7. Known gaps

- **35 entities have no translation row in some language** (3 categories, 5
  subcategories, 9 series, 16 models). Those locales serve the base slug — an
  English word in an Arabic URL. It resolves; it does not rank.
- **71 orphan translation rows** whose parent was deleted. `11-sweep-orphans.mjs`
  is still unwritten.
- **10 test rows are live in the catalog** with `published` / `approved` status,
  including a brand literally named `brand` whose Arabic translation is
  "سامسونج" (Samsung). They are excluded from the backfill by id, not deleted.
- **Localized unit words.** A numeric facet slug appends the Latin unit in every
  language (`15-6-inches` in Arabic). Better than a bare `15-6`, which is
  ambiguous in a URL, but `بوصة` would be better still and needs a translations
  column on `attribute_definitions.value_unit`.
- **`ADMIN_TOKEN` in Directus must equal the app's `REVALIDATE_SECRET`** (or
  `DIRECTUS_ADMIN_TOKEN`). All three flows authenticate with
  `{{$env.ADMIN_TOKEN}}`; if the two environments disagree, every flow call 401s
  silently.
