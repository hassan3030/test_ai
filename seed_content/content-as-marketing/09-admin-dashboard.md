# 09 — Admin & Dashboard

Two audiences, two surfaces:

- **Directus admin** — where content is edited, because it is a content collection
  and Directus already has the editor, the translation UI, and the file picker.
- **Swibba dashboard** — where content is *governed*: the review queue for
  gate failures, coverage reporting, and the unmet-demand report. Things Directus
  cannot express as a collection view.

---

## 1. Directus admin

### `catalog_content` collection setup

```
Icon:              article
Colour:            #2ECDA7
Display template:  {{entity_type}} · {{translations.h1}}
Archive field:     status      Archive value: archived    Unarchive: draft
Sort field:        date_updated (desc)
Note: "Editorial content for catalog landing pages. One row per catalog entity
       per market. Generated by the AI pipeline; edit freely — manual edits are
       preserved because regeneration is gated on source_hash."
```

Field groups, in this order:

| Group | Fields |
|---|---|
| **Target** | `entity_type`, `entity_id`, `primary_market` |
| **Publishing** | `status`, `reviewed_by`, `reviewed_at`, `hero_image` |
| **Content** | `translations` (the translations interface) |
| **AI** *(read-only)* | `ai_generated`, `ai_model`, `ai_generated_at`, `content_version`, `quality_score`, `gate_report`, `source_hash` |
| **Live data** *(read-only)* | `listing_count`, `subscriber_count`, `price_min`, `price_median`, `price_max`, `price_currency`, `last_counted_at` |

The AI and Live-data groups are collapsed by default and every field in them is
`readonly` in the interface. They are diagnostics, not inputs.

#### The `entity_id` problem, and the pragmatic fix

`entity_id` is a soft reference, so Directus renders it as a raw UUID input — which
is unusable for a human. Two mitigations:

1. **Never create rows by hand.** Rows are created by the pipeline, or by the
   dashboard "Generate content" action which supplies the id. The Directus create
   button is hidden for this collection.
2. **Add a computed display field** `entity_label` (string, readonly), written by
   the pipeline as `"Electronics › Phones › Apple › iPhone › iPhone 13"`. It is the
   first column in every list view and makes the collection browsable. It is
   denormalised on purpose, refreshed whenever the pipeline touches the row.

This is the concrete cost of the polymorphic design, and `entity_label` is the
whole of the workaround.

### `catalog_content_translations`

Uses Directus's native translations interface, one tab per language.

| Field | Interface |
|---|---|
| `status` | dropdown, default `draft` |
| `meta_title` | input, `char 60` counter visible |
| `meta_description` | textarea, `char 160` counter visible |
| `keywords` | tags |
| `h1` | input |
| `lede` | textarea |
| `body` | **WYSIWYG**, toolbar limited to `h2 h3 bold italic bullist numlist` |
| `buying_guide` | WYSIWYG, same limited toolbar |
| `price_guidance` | WYSIWYG, same limited toolbar |
| `tl_dr` | textarea, note "40–60 words. Read by AI answer engines with no other context." |
| `faqs` | repeater: `question` (input) + `answer` (textarea) |
| `key_specs` | repeater: `label` + `value` |
| `comparison_notes` | textarea |
| `slug_suggestion` | input, readonly — note "Promoted into the entity's translated slug by the pipeline." |
| `og_image` | file image |
| `word_count`, `reading_time_minutes` | readonly |

The restricted WYSIWYG toolbar is deliberate: the render path only allows
`p h2 h3 ul ol li strong em`, so a toolbar offering tables or images would let an
editor produce content that silently disappears.

### `geo_locations`

```
Display template: {{city}}, {{country}}
Sort: listing_count desc
```
Standard collection; the only note worth adding is on `is_active`: *"Inactive
cities still resolve if someone types the URL, but are never linked or indexed."*

### `catalog_alerts`

**Hidden from the Directus sidebar.** It contains PII, it is never edited by hand,
and everything an operator needs is the aggregate view in the dashboard. Admins
retain access through the collection URL for support cases.

### `ai_settings`

One new field:

```
catalog_content_settings.system_prompt   textarea (monospace), readonly outside dev
```

Placed with the other four prompt fields. Same policy as those: dev-only editing,
enforced in the route handler **and** the form **and** the Directus policy, because
the app's PATCH uses the admin token and bypasses the policy by itself.

> Remember: `getAiSettings()` merges the singleton over `DEFAULT_AI_SETTINGS`.
> Once this field holds a value, editing `src/lib/ai/prompts.ts` has no runtime
> effect. Seed it with `scripts/seed-ai-settings-data.mjs`.

## 2. Dashboard: content governance

New route: `app/[locale]/dashboard/moderation/catalog-content/`, sitting alongside
the existing `moderation/{contacts,feedback,messages,reports,reviews}` and reusing
their `layout.tsx` and access pattern.

Four tabs.

### Tab 1 — Review queue

Everything the quality gate rejected, newest first.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ Review queue                                          14 drafts   3 stale    │
│ [ All ▾ ] [ tier: all ▾ ] [ language: all ▾ ] [ failed check: all ▾ ]         │
├────────────────────────────┬──────┬──────┬──────────────────┬────────────────┤
│ Node                       │ Lang │ Score│ Failed           │                │
├────────────────────────────┼──────┼──────┼──────────────────┼────────────────┤
│ Electronics › Phones ›     │  hi  │ 0.71 │ language_match   │ [View] [Regen] │
│   Apple › iPhone › 13      │      │      │                  │                │
│ Automotive › Cars › BMW    │  ar  │ 0.82 │ body_length      │ [View] [Regen] │
│ Fashion › Shoes › Nike     │  en  │ 0.65 │ sibling_dup,     │ [View] [Regen] │
│                            │      │      │ price_claim      │ [View] [Regen] │
└────────────────────────────┴──────┴──────┴──────────────────┴────────────────┘
```

Row detail expands into the full `gate_report`, so a reviewer sees *which* check
failed and *why* without re-running the model:

```
✗ language_match   Detected script: Latin (expected Devanagari) over 412 words
✓ body_length      412 words (min 250)
✓ meta_title       54 chars
✗ sibling_dup      83% trigram overlap with "Nike Air Force" (max 80%)
```

Actions per row:

| Action | Effect |
|---|---|
| **View** | Deep link into the Directus item, correct language tab pre-selected |
| **Regenerate** | `POST /api/catalog-content/generate` with `force: true` for that entity + locale only |
| **Publish anyway** | Sets `status = published`, `reviewed_by`, `reviewed_at`. Requires a confirmation naming the failed checks — an explicit override, never a one-click bypass. |
| **Archive** | `status = archived`; the page falls back per [03 §8](03-content-pipeline.md) |

Bulk: select rows → regenerate, archive. **No bulk "publish anyway"** — overriding
the gate is a per-page decision, and a bulk override is exactly how thin content
reaches Google at scale.

```
├───────────────┼───────┼────────┼────────┼────────┼────────┼────────┼────────┤
│ Categories    │    22 │  22 ✓  │  22 ✓  │  22 ✓  │  22 ✓  │  22 ✓  │ 22  22 │
│ Subcategories │   118 │ 118 ✓  │ 116    │ 118 ✓  │ 118 ✓  │ 114    │ 98  98 │
│ Brands        │   214 │ 201    │ 180    │ 176    │ 176    │ 170    │ 92  88 │
│ Series        │   640 │ 388    │ 301    │ 288    │ 288    │ 270    │ 44  40 │
│ Models        │  4812 │ 902    │ 610    │ 588    │ 588    │ 540    │ 30  28 │
└───────────────┴───────┴────────┴────────┴────────┴────────┴────────┴────────┘
Indexable /catalog/ URLs: 3,184 · Rendering but noindex: 2,622 · Sitemap entries: 3,184
```

- A cell links to the filtered list of missing nodes for that tier × language.
- "Generate missing" per cell queues a bounded backfill batch through the same
  generator route, with a cost estimate shown before confirming.
- The bottom line reconciles against the live sitemap. If "Sitemap entries" and
  "Indexable" ever disagree, the shared `getIndexationState` has been bypassed
  somewhere — that mismatch is the alarm.

### Tab 3 — Demand

The unmet-demand report from [07 §4](07-availability-alerts.md).

```
┌──────────────────────────┬──────────────┬──────┬──────────┬─────────────┐
│ Node                     │ Narrowing    │ Subs │ Listings │ First asked │
├──────────────────────────┼──────────────┼──────┼──────────┼─────────────┤
│ Apple iPhone 13          │ used, Zagreb │   14 │        0 │ 12 days ago │
│ Samsung Galaxy S22       │ used         │    9 │        0 │  6 days ago │
│ BMW 3 Series             │ rent, Cairo  │    7 │        0 │ 21 days ago │
└──────────────────────────┴──────────────┴──────┴──────────┴─────────────┘
Filters: [ market ▾ ] [ tier ▾ ] [ min subscribers ▾ ] [ supply: zero | any ]
Export CSV
```

Counts only — **never** email addresses. This is a merchandising work queue: it
names exactly which inventory to go source and which sellers to recruit, ranked by
proven demand. The CSV export exists because that work happens outside the product.

### Tab 4 — Pipeline

Operational view of the generator.

- Recent runs from the AI logs (`writeGenerationLog` rows filtered to this
  pipeline): entity, locales, tokens, cost, duration, outcome.
- Rolling 30-day cost, and cost per published page.
- Current `ai_settings` values that affect this pipeline, read-only, with a link to
  the AI settings page: `ai_generation_enabled`, `reasoning_model`,
  `max_output_tokens`, `catalog_content_settings.batch_size`.
- Last refresh-cron result and the next scheduled run.
- A prominent banner when `ai_generation_enabled = false`, because a silent kill
  switch is how a stalled pipeline goes unnoticed for a week.

## 3. Catalog manager additions

The existing catalog managers at `app/[locale]/dashboard/catalog/{categories,
subcategories,brands,series,models}` gain two things.

### Localized slug editing

Each translation tab gets a `slug` input beneath `name`:

```
┌─ Arabic ─────────────────────────────────────────────────────┐
│ Name         [ هواتف                                      ] │
│ URL slug     [ هواتف                                      ] │
│              /ar/catalog/الكترونيات/هواتف                          │
│              ⚠ Changing this creates a redirect from the old  │
│                 URL. Existing links keep working.            │
└──────────────────────────────────────────────────────────────┘
```

- Auto-suggests from `name` on blur when empty, using the same slugify helper the
  pipeline uses.
- Live preview of the resulting URL, built through the resolver so it reflects the
  real chain.
- Inline validation against reserved tokens and in-scope uniqueness before save;
  the route returns `409` with the conflicting row if it slips through.
- The warning is not decorative — changing a slug on a ranking page has real cost,
  and the editor should see that before saving.

### Content status column

Each catalog list view gains a column showing content state per node:

```
● published (7/7)      all languages live
◐ partial (4/7)        some languages live
○ draft                content exists but gated
– none                 no content row
```

Clicking it opens the review queue filtered to that node, or triggers generation
when there is nothing yet. This is where a catalog manager who just created a
brand discovers that its page has no content.

| Capability | Swibba Manager | Moderator | Catalog Manager | Brand Manager |
|---|:--:|:--:|:--:|:--:|
| View review queue | ✓ | ✓ | ✓ | own brand only |
| Regenerate content | ✓ | ✓ | ✓ | own brand only |

| Archive content | ✓ | ✓ | — | — |
| Edit content in Directus | ✓ | ✓ | ✓ | own brand only |
| View coverage | ✓ | ✓ | ✓ | own brand only |
| View demand report | ✓ | ✓ | ✓ | own brand only |
| Export demand CSV | ✓ | ✓ | — | — |
| View pipeline costs | ✓ | — | — | — |
| Edit the AI prompt | dev only | — | — | — |

Enforced in the route handlers, not only in the Directus policy — the dashboard
routes use the admin token and bypass policies on their own. `requireSwibbaManager`
from `src/lib/ai/managerGuard.ts` is the existing guard to build on.

"Own brand only" reuses the `businesses.brand_id` → `brands.managed_by`
relationship that already scopes `app/[locale]/dashboard/brand/*`.

## 5. What is deliberately not built

| Not building | Why |
|---|---|
| A bespoke rich-text editor in the dashboard | Directus's WYSIWYG is already there, already localized, already permissioned. The dashboard governs; Directus edits. |
| A content-versioning UI | `content_version` + Directus revisions cover the need. A diff viewer is a phase-7 nice-to-have. |
| An approval workflow with assignees | The gate is the workflow. Adding human routing on top would reintroduce the bottleneck the pipeline exists to remove. |
| A keyword-research tool | The demand report *is* the keyword research, and it is grounded in real requests from real visitors. |
| Per-page manual `robots` override | Indexation is derived from measurable state. A manual override would drift from the sitemap and break the one-source-of-truth guarantee. |
